# Harmonia Pro Phase 4

Source audit of `main` at `2d43bcc63262606374e1ffda6e3bf4f0d1d86d08` on 13 November 2026. Harmonia Pro is the next in-place release of the single Android app, distributed by direct APK. The baseline is 2.0.0 (versionCode 15), Expo SDK 57, React Native 0.86.3 and Android API 24+. The [Android workflow for this main commit](https://github.com/AlHuDaR/Harmonia-Player/actions/runs/43315613273) passed. See the [release record](release-2.0.0.md) for the owner's S24 Ultra and Mi Box baseline.

## Implementation audit

| Area | Existing implementation | Gap and acceptance test |
| --- | --- | --- |
| Navigation and design | Shared theme presets, focusable controls, English/Arabic direction handling, Home · Search · Downloads · Library on phones, a dedicated TV layout and a TV launcher/banner | Unify the remaining product labels and standardize typography, spacing, focus states and motion through existing components. Check narrow Arabic layouts, large text, TalkBack, reduced motion and physical D-pad navigation. |
| Player and Cast | Local and online playback, queue controls, speed, repeat, A–B loops, local resume points, PiP, background playback, Google Cast and LAN casting of completed downloads | Add a sleep timer that works with the screen locked and survives player view changes. Treat Cast as a separate playback target and test handoffs at expiry. The installed Expo Video SDK exposes local audio/subtitle tracks, but the app lacks a dedicated selector. |
| Library | Persistent favorites, local media, saved tracks, saved links, playlists and history. Search already works by title or artist in track collections. Playback uses the selected list's visible order. | This PR adds title and artist sorting for Favorites, Local media and Saved tracks. Custom playlist editing still needs explicit move controls and persistence tests. Profile large collections on a phone and TV before changing list rendering. |
| Downloads | WorkManager jobs persist across process restart. Downloads already have status/search filters, cancellation, visible-failure retry and offline-file checks. Failed transfers restart cleanly. | Prioritize actionable failure causes, queue controls and storage handling. Validate cancellation during retry, process death, network loss and low storage. Add byte-range resume only for sources with validated ranges and stable validators. |
| Providers and privacy | Existing Android adapters, local imports, app-private storage, and fallbacks for unsupported links. Provider behavior depends on what the source serves. | Preserve the existing boundaries. Use permitted fixtures and the [provider matrix](MULTIPLATFORM_PROVIDER_REVIEW.md) when validating current behavior. Facebook and Snapchat adapters are conditional, and fixture results alone do not establish live coverage. |

## PR order

| Order | Improvement | Customer value | Engineering risk | Performance impact and acceptance |
| --- | --- | --- | --- | --- |
| 1 | Library sorting | High for large collections | Low | Sort the filtered view only when inputs change. Reuse focusable radio controls and the selected-list playback path. Keep the current default order and leave custom playlist sequences intact. |
| 2 | Harmonia Pro branding and shared UI refinement | High across all screens | Low for naming, medium for layout | Use the existing theme and component system for launcher/share label, About, navigation, notifications and TV. Check text scaling, Arabic RTL, TalkBack and D-pad focus before changing navigation behavior. |
| 3 | Sleep timer | High for background listeners | Medium to high | Use a deadline and a playback lifecycle that can enforce it while locked. Verify foreground, lock screen, PiP, queue transitions and Cast. Avoid periodic polling for expiry. |
| 4 | Audio and subtitle track selection | High for multilingual media | Medium | Expose tracks reported by the active local player. Test switching and subtitle-off with a multi-track fixture, source replacement and fullscreen. Expose receiver track selection only when the Cast implementation supports it. |
| 5 | Playlist reordering | High for frequent library users | Medium | Add focusable move controls and persist the existing track ID sequence. Verify reload, active playback continuity and TalkBack announcements. |
| 6 | Advanced download management | High for offline users | High | Improve error recovery and queue/storage controls first. Evaluate transfer resumption separately using controlled interruption and integrity tests. Profile disk usage and background work. |

## Direct APK release

- Keep `com.alhudar.harmonia`, the existing signing configuration, the `harmonia` link scheme and `harmonia-library-v1`. Select a versionCode above the installed release for distribution. Compare signing certificates and verify an in-place upgrade with downloads, imports, playlists, history and preferences intact. See [Android update requirements](https://developer.android.com/google/play/app-updates) and the [signing record](release-2.0.0.md#signing-and-update-compatibility).
