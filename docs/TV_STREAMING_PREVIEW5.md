## Implementation

- On-demand YouTube automatic playback now uses a local clear DASH MPD with multiple indexed H.264 representations in the **same video AdaptationSet**, plus the original preferred compatible AAC audio. Previously each video/audio pair was a single-quality manifest. Media3's default adaptive track selector measures actual transfer bandwidth; this is not an app-side timer swapping entire URLs.
- Auto is offered only with at least two eligible video representations, a positive duration and indexed AAC. Automatic AVC choices are capped at 1080p for conservative television compatibility; other manually selectable formats remain. If no eligible ladder exists, the existing HLS path is preferred when available, otherwise existing fixed formats remain. A single file cannot gain new resolutions through a setting.
- Explicit manual choices are retained. Auto is playback-only in the format list. A download requested from an Auto track resolves a progressive/muxable file instead of exporting the adaptive MPD.
- Android playback receives a bounded 32 MiB network buffer with a 20-second forward target and two-second playback threshold. These are buffering limits, not a guarantee against stalls on insufficient bandwidth.
- Combined phone/TV manifest retains the phone launcher and adds Leanback launch, a generated vector TV banner and optional touch/fake-touch/Leanback hardware features. Common controls/navigation now use native focusable pressables with a visible focus ring; the TV video pane uses more screen height. Signed HLS and generated DASH sources are explicitly routed to the correct adaptive engine. Invisible browsing controls are removed from native TV layout while the expanded player is active, preventing focus from moving behind it. Standard Media3 native controls remain available. No React Native TV fork or additional runtime dependency was introduced.
- The universal build targets ARM32, ARM64, x86 and x86_64. ARM32 matters for Mi Box models with a 32-bit Android userspace. Minimum Android remains API 24; this does not claim Android 6 compatibility or Google TV store certification.

## Live-test blocker and remaining acceptance

A best-effort JVM discovery probe used the existing NewPipe downloader and a public Blender Big Buck Bunny sample (`aqz-KE-bpKQ`), with no credentials or access-control workaround. It failed with **IOException: Unexpected response code for CONNECT: 403**. An independent public-page HEAD request received the same proxy tunnel refusal. This establishes an environment access blocker, not successful extraction and not proof of an application regression. No alternate proxy, authentication or protection bypass was attempted.

`adb devices` found no attached device/emulator. Native decoding, actual bandwidth-driven quality switching, Mi Box launcher presentation, physical remote navigation, HDMI/Bluetooth, background controls and cold/repeated sharing therefore remain **unverified**. The new grouped ladder is a tested implementation boundary, not a claim of end-to-end live YouTube success. The exact Mi Box model/OS and a target public URL were requested; until supplied, compatibility work targets Android TV API 24+ with both ARM userspaces.

The refreshed October 31 npm audit fails with **17 affected entries: 5 high, 10 moderate, 2 low**; affected roots include decode-uri-component, Zod, deepmerge, glob and minimatch. This is an updated advisory database result without dependency changes, not 17 independent proven application exploits. No forced SDK migration or unverified override was applied. The downstream Media3/NewPipe request-policy limitations described in [the earlier repair record](MEDIA_REPAIR_2026_10.md) remain open. This work does not certify completion of the entire original roadmap or remove existing provider restrictions.
