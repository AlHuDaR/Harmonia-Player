# Harmonia 1.5.0 production baseline

This release starts a fresh production installation baseline: package ID
`com.alhudar.harmonia`, version `1.5.0`, Android versionCode `6`.
The package ID must stay unchanged. Every later release needs a higher
versionCode and the same production signing identity. Old test-signed APKs may
require uninstalling; uninstalling deletes app-private files and preferences.
Do not distribute CI test artifacts as the permanent production baseline.

## UI

A compact header opens a dismissible drawer. Home, Samples, Search and Library
are the only bottom navigation items. Downloads remain accessible from Library.
The mini player reserves space above navigation. The full player scrolls on
small screens and keeps transport, formats, favorites, downloads, fullscreen,
PiP and background controls. Channel statistics are removed from the main
player; metadata extraction remains intact. Home shows at most nine real saved
tracks in three columns, with history first. Samples browses recent real library
items; it has no invented catalogue.

Light, Dark and System themes, surface transparency, language, playback and
preferred download format persist in the existing library store. Available
quality is selected from the extractor's real formats in the player. Settings
contains preferences; About, Support and Source Code & Licenses have their own
pages. Donations are disabled until real payment details are supplied.

## Create the permanent key once, manually

AlHuDaR should create and keep the key on a trusted machine. No production key
is generated by prebuild, the build scripts or CI, and no production credentials
are stored in this repository. Java's keytool prompts for passwords; do not put
passwords in command-line arguments or committed files.

Example (run yourself, only once; choose a protected directory outside the repo):

```bash
mkdir -p "$HOME/harmonia-signing"
chmod 700 "$HOME/harmonia-signing"
keytool -genkeypair -v \
  -keystore "$HOME/harmonia-signing/harmonia-production.jks" \
  -alias harmonia-production -keyalg RSA -keysize 4096 -validity 10000
chmod 600 "$HOME/harmonia-signing/harmonia-production.jks"
keytool -list -v -keystore "$HOME/harmonia-signing/harmonia-production.jks"
```

Record the certificate SHA-256 fingerprint and alias. Keep at least two encrypted
backups of the keystore in separate secure locations. Store the passwords in a
password manager; verify that a backup opens with keytool before distributing
1.5.0. Loss of the direct-install APK signing key prevents compatible future APK
updates. Never replace it just because a new build machine is used.

## Build every production APK/AAB with that key

The existing `HARMONIA_PRODUCTION` plugin checks all four signing variables and
fails if any is missing; it never falls back to test signing when production is
requested. Use an absolute keystore path, outside the checkout. Provide passwords
through protected environment variables/secrets. For an interactive local shell:

```bash
export HARMONIA_PRODUCTION=1
export HARMONIA_STORE_FILE="$HOME/harmonia-signing/harmonia-production.jks"
export HARMONIA_KEY_ALIAS=harmonia-production
read -rsp 'Keystore password: ' HARMONIA_STORE_PASSWORD; echo
export HARMONIA_STORE_PASSWORD
read -rsp 'Key password: ' HARMONIA_KEY_PASSWORD; echo
export HARMONIA_KEY_PASSWORD
npm ci
npm run build:android-release
unset HARMONIA_STORE_PASSWORD HARMONIA_KEY_PASSWORD
```

Do not enable shell tracing (`set -x`) when secrets are loaded. On a protected CI
runner, supply the same variables via encrypted secrets, materialize the backed-up
keystore outside the checkout, and remove that temporary copy after building.
The existing PR workflow deliberately uses test signing and has no production
secrets. Test APKs/AABs are identified as such by the builder.

Outputs:

- `artifacts/Harmonia-Player-arm64.apk`: ARM64 devices, including S24 Ultra.
- `artifacts/Harmonia-Player-universal.apk`: direct install, all four Android ABIs.
- `artifacts/Harmonia-Player.aab`: Google Play upload, all four Android ABIs.

Verify APK signatures with Android build-tools `apksigner verify --print-certs`.
Use `jarsigner -verify` and `keytool -printcert -jarfile` for the AAB. Compare the
certificate fingerprint against the recorded production fingerprint before
publishing. The PR workflow also checks bundled JS, ABI contents and NewPipe.

### Google Play signing identity

An AAB upload key and Google Play's app signing key serve different roles. Play
signs installed APKs using the app signing key, not necessarily the AAB upload
key. To let users move between a directly installed production APK and Google
Play without uninstalling, configure Play App Signing to use your existing
production app signing key during initial setup. If Google generates a different
app signing key, the direct APK and Play installation have different identities;
cross-channel updates cannot be assumed to work. Reuse the permanent upload key
for future AAB uploads, and reuse the permanent APK/app signing identity for
future installations. A Play upload-key reset does not change the APK signing
identity and does not solve a lost direct-install signing key.

## Storage and future upgrades

The AsyncStorage key stays `harmonia-library-v1`. Private download and import
paths remain unchanged (`documentDirectory/downloads` and
`documentDirectory/imports`). Startup does not clear the library or delete
completed media; interrupted `.part` files use the existing cleanup behavior.
Old settings gain defaults without discarding media, playlists, favorites,
history or language. No persistent directory is renamed.

Normal update: same package ID + same production signing identity + higher
versionCode. Install with Android's update flow or `adb install -r`; do not
uninstall or clear app data. This preserves the app's files and preferences.
User-initiated deletion and uninstall still remove the selected data.

## Physical-device checks before production distribution

- Android Back dismisses the drawer/full player; tapping outside or selecting a
  drawer item closes it.
- Check English and Arabic, Light/Dark/System, portrait, landscape and large fonts.
- Confirm the mini player sits above navigation and content remains reachable.
- Test NewPipe search, playback, format changes, download, offline playback,
  imported media, previous/next, shuffle, repeat and favorites.
- Test background/lock-screen/Bluetooth media controls and interruption behavior.
- Test manual and automatic PiP, fullscreen and rotation.
- Test YouTube VIEW/SEND links from WhatsApp and Android supported-link settings.
- Install the production baseline, create library data, then test a higher
  versionCode build with the same key via `adb install -r`. Check every stored
  media file and preference survives. Do not test this with differing CI keys.

Google Play upload/publication and device testing are separate from creating
this PR. A valid AAB alone does not establish Play policy eligibility.
